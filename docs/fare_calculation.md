# 運賃計算の再設計メモ（2025年4月改定準拠）

2026-07-13 実施。プロジェクト監査で見つかった運賃計算の不具合を起点に、
`backend/app/fare.py` と `backend/data/fare_table.json` を JR西日本の
2025年4月1日改定後の運賃体系に合わせて再実装した記録。

## 発端: 監査で見つかった問題

1. **端数キロの表引きバグ（重大）**
   旧 `km_to_fare` は `from_km <= km <= to_km` で表を引いており、帯が
   `1–3, 4–6, …` と整数区切りのため 3.5km などの端数がどの帯にも
   マッチせず、フォールバックの最終帯（最高額 ¥1,320）を返していた。
   JR の正式ルールは営業キロの 1km 未満を**切り上げてから**表引き。
2. **運賃表の出所が不正**
   旧テーブルの `fare_ic: 133` など 1円単位の IC 運賃は JR東日本の
   体系の値。JR西日本は 1円単位 IC 運賃を導入しておらず、
   ICOCA 運賃 = きっぷ運賃（10円単位）。
3. **運賃体系の未対応**
   電車特定区間（京阪神）の割安運賃・地方交通線（加古川線）の換算キロ・
   関西空港線の加算運賃・特定運賃がすべて未対応だった。
4. **2025年4月1日の改定が未反映**
   「大阪環状線内」区分の廃止、電車特定区間の拡大・平準化。

## 新しい運賃計算の仕組み

データ: `backend/data/fare_table.json`（手編集する場合は出典に忠実に）

```
revision            : "2025-04-01"
trunk               : 幹線 普通運賃表（toKm 昇順、切り上げ後キロで走査）
denshaku            : 電車特定区間 普通運賃表（2025-04-01 改定後、バリアフリー料金込み）
local               : 地方交通線 普通運賃表（B表。帯が不規則、100km まで）
localLineIds        : 地方交通線の路線ID（加古川線 "I"・播但線 "J"）
localConversionFactor : 換算キロ係数 1.1
denshakuStationIds  : 電車特定区間に属する駅IDの集合
airportSurcharges   : 関西空港線の加算運賃（O-Dペアごと、二重加算しない）
specificFares       : 特定運賃（発着駅ペア・双方向、表引きより優先）
```

計算手順（`fare.py: compute_fare`）:

1. 距離ベース Dijkstra の最短経路からエッジ列を復元
2. **特定運賃**: 発着ペアが `specificFares` に一致すればその額を即返す
3. 経路の全駅が電車特定区間内 → `denshaku` 表
4. 地方交通線を含む場合（`localLineIds`）
   - 全区間が地方交通線 → 営業キロで `local`（B表）
   - 幹線と混在・合計営業キロ 10km 以下 → 営業キロ合計で `local`（B表）
   - 幹線と混在・10km 超 → 運賃計算キロ（幹線の営業キロ + 地方交通線の
     営業キロ×1.1）で `trunk`（A表）
5. キロは `math.ceil`（浮動小数誤差を吸収してから）→ `toKm` 昇順走査。
   表の最大キロ超過は `ValueError`（`/fare` は 400 を返す）
6. 経路が関空加算区間に触れる場合は O-D に一致する加算運賃を 1 件だけ加算

IC ときっぷは同額のため内部は単一額。API レスポンス（`fareIc` /
`fareTicket`）は互換のため両方に同じ値を入れており、フロントは無変更。

## 地方交通線 B表の対応（2026-07-25）

対象は加古川線 `I` と播但線 `J`。**播但線が `localLineIds` に未登録**だったため、
姫路〜寺前 29.6km が幹線表 26〜30km 帯の 510円（実売 590円）になっていた。

B表の帯は幹線表と違って**不規則**（`1-3 / 4-6 / 7-10 / 11-15 / 16-20 / 21-23 /
24-28 / 29-32 / 33-37 / …`）で、11km 以上の運賃額は幹線表と同額・帯の境界だけが
約 1/1.1 にずれる（= 換算キロ×1.1 を営業キロの表に焼き直したもの）。
そのため「幹線表で近似」は帯境界付近で必ずずれる。低キロ帯だけは独自で、
7〜10km は幹線 200円に対し B表 210円。

出典は [JR線ご利用案内](https://jr-group.jp/nishinihon-fare/)（二次資料）。
JRおでかけネットの公式電子ブックは画像ベースで、機械抽出すると電車特定区間表を
「地方交通線」と取り違えた値が返るため採用できなかった。代わりに
①上記の構造整合（11km 以上が幹線表と同額）②Yahoo!路線情報の実売額 6 区間との
突き合わせ、で検証した:

| 区間 | 営業キロ | 判定 | 実装 | 実売 |
|---|---|---|---|---|
| 姫路〜寺前（J のみ） | 29.5km | 全区間地交線 → B表 | 590 | 590 |
| 加古川〜谷川（I のみ） | 48.0km | 全区間地交線 → B表 | 990 | 990 |
| 加古川〜西脇市（I のみ） | 30.8km | 全区間地交線 → B表 | 590 | 590 |
| 加古川〜厄神（I のみ） | 7.3km | 全区間地交線 → B表 | 210 | 210 |
| 東加古川〜神野 | 8.3km | 混在10km以下 → B表 | 210 | 210 |
| 東加古川〜厄神 | 10.9km | 混在10km超 → 換算キロでA表 | 240 | 240 |

## レビューで検出した実装ミス（修正済み）

- サブエージェントの初版は阪和線の電特を日根野で打ち切っていた
  → 和歌山側 9 駅 + 東羽衣を `denshakuStationIds` に追加
- 特定運賃が未実装で大阪→京都が 750円 と表示されていた
  → `specificFares` 5 ペアを実装（実売 580円）
- 関空加算運賃の初版は経由駅ごとに加算を合算していた（日根野→関空が
  220+160+170=550円）→ O-D 一致 1 件のみ適用に修正

## 既知の制限（要検証・未対応）

- ~~特定運賃は主要 5 ペアのみ収録~~ → 2026-07-16 完全収録済み。
  [2025-04-01改定プレスリリース](https://www.westjr.co.jp/press/article/items/240515_00_press_keihanshin_unchin.pdf)
  別紙4（改定後の特定区間運賃の確定表）から pypdf でテキスト抽出し、
  グラフ収録駅間の全 341 ペアを機械転記（駅名は graph.json と突合、
  「ケ→ヶ」正規化のみ手当）。既存 5 ペアとの一致・PDF 目視 8 ペアの
  抜き取り照合で検証済み。別紙4 には所定運賃と同額の区間（網掛け）も
  含まれるが、同額のため挙動に影響しない
- ~~幹線＋地方交通線の合計 10km 以内は B表の転記が取れず幹線表で近似~~
  → 2026-07-25 B表を正式対応（下記「地方交通線 B表の対応」）
- B表の最終帯 92〜100km（1,880円）は、幹線表の対応帯（101〜120km:1,980円）
  から導かれる額と一致せず**要検証**。グラフ内の地方交通線は最長でも
  加古川線 加古川〜谷川 48.0km のため、この帯には到達しない
- 幹線表は 200km まで、B表は 100km まで収録（大阪近郊区間の最短経路運賃では十分）
